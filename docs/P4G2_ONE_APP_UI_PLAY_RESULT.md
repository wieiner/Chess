# P4G2 Phase 19 - One-App UI Play Result

Date: 2026-06-27

## Purpose

Verify that one `ChessOnlineApp` instance can drive an online match against the public Hetzner HTTP 80 server through the UI path, not only through the command-line smoke tool.

## Build

Command:

```powershell
dotnet build src\ChessOnlineApp\ChessOnlineApp.csproj -c Release -p:Platform=x64
```

Result:

```text
PASS
```

## UI Automation Support

The P4G board cells now expose stable automation metadata:

```text
AutomationId: P4GCell_<x>_<y>_<z>
Name: Cell (x,y,z) <piece>
HelpText: coordinate/index/piece/legal target summary
```

This is UI-layer-only and does not change Chess3D rules, online protocol DTOs, server authority, save/load/replay, or native ABI.

## Automated One-App Click Path

An operator-style Windows UI Automation script launched:

```text
src\ChessOnlineApp\bin\x64\Release\net8.0-windows\ChessOnlineApp.exe
```

It executed the following visible UI path:

1. Select `3D Relay`.
2. Click `Use Hetzner HTTP`.
3. Click `Check Health`.
4. Click `Check Diagnostics`.
5. Click `Create Two Test Players`.
6. Click `Create Test Match With Two Local Clients`.
7. Click `Ready Both`.
8. Click `Start Game`.
9. Click `Request Snapshot`.
10. Click board source cell `P4GCell_4_4_0`.
11. Click `Submit Selected Preview Action`.
12. Click `Request Action Log`.

The default profile selector was left on:

```text
classic-six-side-3d-8x8x8-v0.1
```

The temporary automation log was written under:

```text
.tmp\manual-smoke\p4g2-one-app-ui-automation-20260627.log
```

That raw log is ignored and is not committed.

## Boundary

This phase did not touch:

- 443/TLS/domain;
- x-ui/Xray;
- Outline;
- Albatronix Docker;
- Unreal SYServer;
- Nginx config;
- UFW/firewall.

Temporary users were generated by the client. Tokens and generated passwords were not printed or committed.

## Known Limitations

- This was an automated one-app smoke over the current WPF control tree, not a polished screenshot-based QA run.
- The tested UI action path used Classic default profile. Asgard server-preview action is covered by the Phase 18 remote smoke and can be repeated manually through the same UI profile selector.
- Full 3D online board polish remains future work; this phase proves practical connect/match/start/snapshot/legal-preview/action-log flow.
