# Physical 11x11 Input Result

Phase 20 proves the physical-input workflow as a headless product contract.
It uses the same managed draft, portable state, native cube, visual descriptor,
and atomic file APIs used by RubikApp.

## Solved draft workflow

1. Create an empty 11x11 six-face draft.
2. Fill U/R/F/D/L/B with the solved color scheme.
3. Run structured draft validation and cubie inventory validation.
4. Apply the portable facelets to a fresh native 11x11 cube.
5. Build the complete 726-sticker shell visual description.
6. Save a `.rubik.json` document atomically.
7. Create a fresh cube (the reset boundary), load the file, and apply it.
8. Compare all facelets and the canonical state hash.

Every step passes in `RubikStateContractTests`.

## Legal scramble workflow

A deterministic legal 20-turn state is generated by the native 11x11 engine,
converted to the portable physical format, validated, rendered, saved, loaded,
and saved as a second independent copy. The copy preserves the exact 726
facelets and canonical hash. Temporary fixtures live only under the test temp
directory and are removed after the run.

## Solver readiness

Both states pass basic counts and corner/wing/center-orbit inventory. The
reported level is `CubieInventory`; `orientationProven`, `parityProven`, and
`solverReady` remain false. This is a successful physical input workflow, not
a claim that an arbitrary 11x11 state can already be proved solvable or solved.
